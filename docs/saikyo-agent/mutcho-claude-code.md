## 3. 要点を「最強エージェント化」の材料に整理

### 3-1. 考え方（むっちょ流の軸）★

| 軸 | 中身 | このリポジトリでの意味 |
|---|---|---|
| 複利 | 一度教えたことを残して、次から言わなくて済む形にする | 指摘・手順を CLAUDE.md／スキルに貯める（既に「同じ指摘2回で追記提案」ルールあり） |
| 置き分け | CLAUDE.md＝短い決まりだけ／手順の全文＝スキル | CLAUDE.md 200行以内ルールと同じ方向 |
| 依頼の3点セット | 目的・ガードレール・終了条件 | 見積・届出を頼む時の型にできる |
| AI社員（役割分担） | 担当ごとに分けて任せる | 見積係・着工届係・設置届係・事務係…に分ける |
| 人が残る所を決める | 全部は任せない | 送信・提出・最終判断は越前さん（既存の4Dルールと一致） |

### 3-2. 機能の使い分け（一般的なやり方・公式ドキュメント準拠）

| 機能 | たとえ | 何を入れるか |
|---|---|---|
| CLAUDE.md | 毎朝の朝礼で必ず言うこと | 会社・人物・絶対条件・返事の仕方だけ |
| スキル | 業務マニュアルの棚（必要な時だけ開く） | 見積・着工届・設置届などの手順と見本の場所 |
| フック | 自動ゲート（必ず通る関所） | 送信前確認、サーバーの削除・名前変更ブロック |
| サブエージェント | 部下に別室で作業させる | 過去物件の検索、図面・数量の拾い、チェック役 |
| MCP（連携） | 外部の窓口をつなぐ電話線 | Gmail・カレンダー・Googleドライブ（済）、会社サーバー |
| プラグイン | スキル＋フック等のセット商品 | superpowers（導入済み） |
| 定期実行（Routines／スケジュール） | 決まった時間に動く目覚まし | 毎朝の予定・メール要約、月末の残業集計 |

### 4-1. 新しいスキル候補（優先順）

| 優先 | スキル名（案） | 中身 |
|---|---|---|
| 1 | `mitsumori` | 見積・概算見積・予算書・見積根拠図面。サーバーの過去見積を見本に、単価表・歩掛を参照 |
| 2 | `chakko-todoke` | 着工届一式（表紙・案内図・概要表・アイソメ・圧損計算・機器図）のチェックリストと作る順番 |
| 3 | `secchi-todoke` | 設置届一式（表紙・試験結果報告書・配線試験・竣工単線図） |
| 4 | `shobosho-shoshiki` | 提出先消防署ごとの書式メモ（東京消防庁を基本に、署ごとの違いを貯める） |
| 5 | `kinmu-shukei` | 野口さんの勤怠・残業集計（日報スキルと連動） |
| 6 | `irai-template` | 依頼の型「目的・ガードレール・終了条件」を自動で聞き返す |

### 4-2. AI社員（サブエージェント）候補

| 役割 | 仕事 | 権限 |
|---|---|---|
| 見積係 | 数量拾い・単価当て・見積書下書き | 読む＋下書き作成のみ |
| 届出係 | 着工届・設置届の書類一式の下書き | 読む＋下書き作成のみ |
| 資料探し係 | サーバー・メールから見本や過去物件を探す | **読むだけ** |
| チェック係 | 数字・日付・名前・法令根拠の照合（teishutsu-check を使う） | 読むだけ |
| 秘書係 | 予定・メール要約・日報 | 送信・削除は越前さんの許可制 |

### 4-3. フック追加候補

| いつ | 内容 |
|---|---|
| サーバー上のファイル操作の前 | 越前フォルダ以外の削除・移動・名前変更を**自動で止める**（絶対条件の強制） |
| 見積・届出を作り終えた時 | teishutsu-check を必ず通すよう促す |

### 4-4. CLAUDE.md に足す候補（短く1〜2行だけ）

- 「頼まれた仕事に目的・ガードレール・終了条件が無ければ、作る前に聞く」
- 「業務ごとの担当（サブエージェント）表」へのリンク1行
